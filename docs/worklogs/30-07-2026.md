## 4. Bug "UI chớp đen" (Owner báo sau khi merge FSM)

> **Đọc cả mục.** Lần chẩn đoán đầu (shadow ping-pong) tìm ra một lỗi thật nhưng **không phải**
> nguyên nhân Owner nhìn thấy — Owner báo lại "vẫn còn chớp tắt". Root cause thật là **Bloom**, ở
> tiểu mục cuối.

Owner báo màn hình đôi lúc **chớp đen rất nhanh**, tần suất **tăng nhẹ** sau code FSM.

### Lần 1 (chưa trúng): ping-pong three.js ↔ R3F, mỗi React re-render = rebuild toàn bộ shadow map

`ENV_CONFIG.shadows.type` là `THREE.PCFSoftShadowMap` — **hằng số đã deprecated**. Chuỗi nhân quả:

1. `three/build/three.module.js` — `WebGLShadowMap.render()`:
   ```js
   if ( this.type === PCFSoftShadowMap ) {
     warn('WebGLShadowMap: PCFSoftShadowMap has been deprecated. Using PCFShadowMap instead.')
     this.type = PCFShadowMap        // ← MUTATE giá trị của mình
   }
   ```
2. `@react-three/fiber` `configure()` chạy **mỗi lần `<Canvas>` render**, `Object.assign(gl.shadowMap, shadows)`
   ghi `PCFSoftShadowMap` trở lại, rồi:
   ```js
   if (oldEnabled !== gl.shadowMap.enabled || oldType !== gl.shadowMap.type) gl.shadowMap.needsUpdate = true
   ```
   `oldType` = `PCFShadowMap` (three vừa ghi) ≠ `PCFSoftShadowMap` (config) → **`needsUpdate = true`**.
3. → rebuild **toàn bộ** shadow map trong frame đó → frame tối → chớp đen. Rồi three lại downgrade
   → lặp vô hạn ở mỗi re-render.

**Lỗi này có TRƯỚC refactor.** Refactor làm nó lộ ra nhiều hơn vì `currentState` + `cameraMode` giờ
đẩy qua context → `CharacterViewer` (chủ `<Canvas>`) re-render **mỗi lần đổi state** thay vì chỉ khi
đổi motion. Đúng như Owner mô tả: "tần suất tăng 1 chút".

### Đo trước/sau (đếm warning — nó phát ra **từ trong** `WebGLShadowMap.render()`, tức đúng event rebuild)

| Tình huống | Trước | Sau |
|---|---|---|
| Boot + greeting | 4 rebuild | **0** |
| 4 FSM transition | +4 | **+0** |
| 1 exercise (kèm camera hips→head) | +2 | **+0** |
| Ngồi im 5s | +0 | +0 |

### Fix

1. 🔑 **`environmentConfig.ts`: `PCFSoftShadowMap` → `PCFShadowMap`** — chính là giá trị three.js
   **vẫn đang dùng** (nó tự downgrade), nên **hình ảnh không đổi**, chỉ khác là không còn ping-pong.
   Một dòng này xoá hẳn triệu chứng, độc lập với số lần React re-render.
2. `CharacterViewer.tsx`: hoist `gl` / `camera` / `shadows` của `<Canvas>` ra **module const** — trước
   đó là object literal inline nên `configure()` nhận object mới mỗi render.
3. `CharacterViewer.tsx`: `new THREE.AxesHelper(3)` mỗi render → `useMemo` (R3F đang detach/dispose
   rồi attach lại object mỗi lần re-render).
4. `ScenePostProcessing.tsx`: `memo()` — component không nhận prop, chỉ đọc config tĩnh.
5. `MotionContext.tsx`: `useMemo` cho context value — trước đó object literal inline = value mới mỗi
   lần provider render → mọi consumer re-render kể cả khi dữ liệu của nó không đổi.

Verify sau fix: **11/11 + chat test vẫn xanh**, `tsc` + `build` xanh, avatar render bình thường
(ảnh scratchpad `shot2.png`).

### ⚠️ Fix trên KHÔNG dứt điểm — Owner báo lại "vẫn còn chớp tắt"

Fix shadow ping-pong là **thật** (rebuild 4→0) nhưng **không phải nguyên nhân** Owner nhìn thấy.
Phải đo lại bằng pixel thật thay vì proxy.

#### Vì sao 2 lần đo đầu vô nghĩa

- **Headless Chromium không chạy compositor thật**: `readPixels`/`drawImage` từ canvas WebGL trả về
  rỗng; CDP screencast chỉ ra **39 frame/20s**. Mọi kết luận "0 frame đen" từ headless là vô giá trị.
- Probe tự viết cũng sai: tôi tô nền magenta rồi `drawImage` — luma 170 chính là **magenta**
  (255+0+255)/3, tức "không vẽ được gì", không phải "màn hình tối".
- Chạy lại **headed** + `--disable-backgrounding-occluded-windows` (+ `bringToFront`) mới có
  ~59fps thật. Cũng chính vì rAF bị throttle mà FSM đứng ở `greeting` mãi → 2 lần test timeout.

#### Đo đúng: CDP screencast headed, 1148 frame/19.5s, đếm frame có luma < 75% median

Frame đen thật đọc **luma 17.8** giữa các frame bình thường **~220** — tức **đúng 1 frame đen đơn lẻ**,
không liên quan sự kiện app nào. Ảnh frame đó: **vùng canvas đen đặc, UI HTML (nav, logo) vẫn bình
thường** → lỗi nằm ở đường render WebGL, không phải DOM.

#### Bisect

| Cấu hình | Frame đen / 19.5s |
|---|---|
| Bật hết | 4 |
| Tắt SSAO | 3 → **không phải SSAO** |
| Tắt ContactShadows | 5 → **không phải ContactShadows** |
| Tắt cả EffectComposer | **0** |
| **Tắt Bloom, giữ nguyên phần còn lại** | **0** ← khoanh trúng |
| Bloom bật lại kèm `mipmapBlur` | 6 → đổi đường blur **không cứu được** |

#### Fix

`ENV_CONFIG.postProcessing.bloom.enabled = false` + `ScenePostProcessing` gate theo cờ đó (dựng mảng
effect thay vì `&&` inline, vì `EffectComposer` type children là element nên `false` là lỗi compile).

Đánh đổi: Bloom đang ở `intensity 0.15` / `threshold 0.85` — gần như không nhìn thấy, trong khi nó
gây **1 frame đen mỗi ~3-5s**. Không phải quyết định khó. Cờ vẫn còn để Owner bật lại; comment trong
config ghi nguyên bảng số đo để lần sau ai bật lại thì biết phải đo lại thế nào.

Verify cuối: **0 frame đen** trên 1148 frame, min luma 215.6 (trước: 17.8). FSM suite **11/11** +
`tsc` + `build` xanh.

#### Thứ khác tìm được trong lúc đo (đã sửa luôn)

Load clip **lần đầu** chặn main thread: `thinking_intro` **111ms**, `bored` **214ms** (warm chỉ
21-40ms) → render loop khựng đúng lúc user vừa hỏi câu đầu tiên. Thêm
`AnimationRegistry.prefetchStatic()` — warm mọi clip tĩnh qua `requestIdleCallback`, mỗi callback 1
clip, gọi sau khi boot xong. Sau fix: max frame gap **35ms** ở mọi phase.
