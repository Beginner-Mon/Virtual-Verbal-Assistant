## Vì sao

Frontend phải biết **bốn origin API** (`VITE_API_BASE_URL`, `VITE_CRUD_API_URL`,
`VITE_ASSET_BASE_URL`, `VITE_AUTH_API_URL`) — mỗi cái một chỗ cấu hình sai được, và
hai cái đã sai thật trong tuần. Mỗi service tự lo CORS, tự lo auth. Không có tầng nào
đặt được chính sách chung, và không có lớp chặn lưu lượng nào.

## Kiến thức của tôi lỗi thời — ba lần

Đây là bài học lớn nhất của phiên này, và nó lặp lại đủ nhiều để đáng ghi thành mục
riêng.

**Lần 1 — loại `/chat` khỏi gateway.** Tôi khẳng định "API Gateway không hỗ trợ
response streaming" và dùng đó làm lý do quyết định. Sai: **REST API có, từ 11/2025**

*"time-to-first-byte for generative AI applications like chatbots"* và *"server-sent
events"*. Streaming cũng nâng integration timeout lên **15 phút** và vượt trần payload
10 MB.

Phát hiện được **chỉ vì Owner yêu cầu dùng plugin `aws-core`** và tra tài liệu thật.

**Lần 2 — số liệu độ trễ.** Tôi trích 29,3s từ `05-08-2026.md:64` như hiện trạng. Con

cho biết thực tế ~15s. Grep toàn bộ worklog 16→20/08: **không có số đo nào mới hơn**.

## Vì sao REST API chứ không HTTP API

| | REST | HTTP |
|---|---|---|
| **Response streaming (SSE)** | ✅ | ❌ |
| **`/chat` vào được** | ✅ | ❌ vĩnh viễn |
| WAF · usage plan · X-Ray | ✅ | ❌ |
| Payload format | 1.0 → sửa handler | 2.0, khớp sẵn |
| Giá ở 100k req/tháng | $0,35 | $0,10 |

Dòng thứ hai quyết định. Owner muốn gộp *mọi* endpoint; HTTP API loại `/chat` vĩnh
viễn, tức chọn nó là tự khoá mình vào một cuộc migrate. Giá giữ cửa mở: ~10 dòng sửa
handler và **25 xu một tháng**.

## Kiến trúc — và một lần Owner sửa tôi

Bản đầu tôi đặt **CloudFront đứng trước cả API** để có "một hostname duy nhất". Owner
chất vấn, và chất vấn đó đúng.

Cái nó mua: bớt **một** biến môi trường, cộng cache biên cho `/characters` — mà catalog
có 4 dòng và `handler.py:39-45` đã tự đặt `Cache-Control: max-age=300`, tức trình duyệt
vốn đã cache 5 phút. Tiết kiệm ~2.000 lượt gọi Lambda/tháng ≈ **0,7 xu**.

Cái nó tốn: một chặng mạng, và **ba cái bẫy im lặng** — quên `OriginRequestPolicy` là
401 toàn bộ; quên `CACHING_DISABLED` là CloudFront phục vụ session người này cho người
khác (lỗ hổng ở tầng **trên cả RLS**); quên `ALLOW_ALL` là POST/DELETE bị chặn.

Dấu hiệu rõ nhất là chính câu hỏi của Owner: **sơ đồ đó khiến người đọc không biết cái
gì nằm ở đâu.** Kiến trúc phải giải thích mới hiểu được là đang che giấu.

**Kết quả sau khi sửa** — mỗi thứ một việc:

```
Amplify Hosting  →  app React
REST API Gateway →  MỌI lời gọi backend (characters, sessions, me, health)
CloudFront → S3  →  CHỈ file .vrm 9-17 MB
```

`.vrm` không qua gateway vì hai lý do là số: trần payload buffered **10 MB** (3/4 model
vượt), và data transfer gateway **$0,09/GB không free tier** vs CloudFront **$0,085/GB
có 1 TB/tháng miễn phí vĩnh viễn**.

Và ba cái bẫy **biến mất cùng thiết kế sinh ra chúng**. `VvaAssetStack` giờ đơn giản
hơn trước khi bắt đầu.

### Stage làm version, không thêm tiền tố đường dẫn

`stage_name="v1"` → `https://<id>.execute-api.../v1/sessions`. Versioning **miễn phí,
không tốn dòng code nào**.

Quan trọng: với REST API, `event["path"]` **không kèm stage**, nên handler nhận
`/characters` và chạy nguyên vẹn. Thêm tiền tố `/api/v1` thật vào đường dẫn thì
`event["path"]` thành `/api/v1/characters`, `handler.py:115` so segment đầu với
`"characters"` → **404 mọi request**.

### Handler đọc cả hai format, không đổi cứng sang 1.0

```
format 2.0   event["rawPath"]                event["requestContext"]["http"]["method"]
format 1.0   event["path"]                   event["httpMethod"]
format 1.0   event["requestContext"]["path"]  ← KÈM STAGE. Không bao giờ đọc cái này.
```

Đọc cả hai nghĩa là cùng một package chạy được sau Function URL lẫn REST API — chuyển
gateway thành việc hạ tầng, không phải việc code. Đọc nhầm `requestContext.path` là
404 mọi request trong khi function, integration và IAM policy đều trông đúng.

### 🔴 Wildcard CORS lộ ra

`shared/response.py` để cứng `Access-Control-Allow-Origin: "*"`. Nó **bị CloudFront
che** nhờ `origin_override=True` — bỏ CloudFront khỏi đường `/characters` là nó thành
chính sách thật.

Với catalog công khai thì `*` không phải lỗ hổng. Nhưng **không ai chọn nó — nó chỉ lộ
ra**, và nó lệch với allow-list ở mọi chỗ khác. Đổi sang đọc `ALLOWED_ORIGINS` như
`crud_app.py:39-47`, echo Origin của caller, thêm `Vary: Origin`.

`begin_request(event)` dùng biến module thay vì thêm tham số vào mọi `success()`/
`error()`: Lambda xử lý đúng một request mỗi lần, nên mối nguy đồng thời khiến pattern
này sai trong web server **không tồn tại ở đây**.

### Cổng biến môi trường lúc build

`characters.ts:11` rơi về `localhost:8000` khi thiếu biến — hỏng im lặng, đúng sự cố
tuần này. Fallback đó **có lý do**: bản trước `throw` lúc import và ship ra màn hình
trắng. Nên kiểm ở **build**, không ở runtime.

`vite.config.ts` fail build khi thiếu `VITE_API_GATEWAY_URL` / `VITE_ASSET_BASE_URL` /
`VITE_AUTH_API_URL`, hoặc khi **có** `VITE_AUTH_DISABLED`. `npm run dev` vẫn tự do.

CI có thêm một bước **cố tình bỏ một biến và khẳng định build phải đỏ** — một cổng
không tự chứng minh được là nó còn chạy thì không phải cổng.

## 🔴 Bẫy thứ tự deploy — phát hiện lúc `cdk diff`

`VvaAssetStack` đang **import** export Function URL ARN của `VvaCharacterStack`. Xác
minh trên AWS:

```
aws cloudformation list-imports --export-name "VvaCharacterStack:ExportsOutput...FunctionArn..."
→ IMPORTS   VvaAssetStack
```

**CloudFormation từ chối xoá một export còn được import.** Deploy `VvaCharacterStack`
trước sẽ fail:

```
Cannot delete export ... as it is in use by VvaAssetStack
```

Thứ tự bắt buộc: **AssetStack bỏ import trước, CharacterStack bỏ export sau.** Đã ghi
vào `infra/deploy.ps1` thay vì vào trí nhớ.
