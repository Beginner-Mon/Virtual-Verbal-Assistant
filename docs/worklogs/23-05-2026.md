## 2. Architecture Decisions (N's input)

### Flow thay doi lon: Memory chay TRUOC Planner

```
v2.2:  manager → memory → retrieval → reasoning → validator → conversation → dispatch
v2.4:  memory → planner → retriever_agent → synthesizer → grader → conversation
```

Ly do: Planner can memory context (STM + user profile) de classify intent + len plan chinh xac. Manager cu classify "mu" khong co context.

Trade-off: Memory LTM chi co raw query (chua co expanded_query). Chap nhan vi LTM tim user history, khong phai domain knowledge.

### Manager = Planner (renamed + upgraded)

- Manager cu: chi classify intent + expand query
- Planner moi: classify intent + expand query + **structured plan output** (Pydantic model)
- Plan chua: `required_outputs`, `search_strategy`, `constraints_detected`, `needs_clarification`
- Planner **chi len ke hoach**, Retriever Agent execute

### Retriever Agent = Tool Executor

- Nhan plan tu planner → chon tools → goi song song
- pgvector = `@tool` (in-process, 0ms network overhead)
- Kimodo + web_search = MCP tools (external services)
- ToolNode parallel execution

### Memory Architecture moi

| Component | Storage | Detail |
|-----------|---------|--------|
| STM | Redis | Max 3 Q&A pairs, FIFO, TTL 2h |
| LTM | PostgreSQL + pgvector | Conditional — chi trigger khi user query co recall keywords |
| Session | PostgreSQL | Full conversation history, support reopen |

LTM trigger: regex keyword matching ("nho", "tuan truoc", "lan truoc"...), khong dung LLM.

LTM flow:
- 0 sessions match → planner decides (knowledge query or inform user)
- 1 session match → pgvector search within session → return results
- 2+ sessions match → ambiguous → planner route to clarify

Temporal: calendar week (Monday-Sunday), +-3 day expansion if no match.
