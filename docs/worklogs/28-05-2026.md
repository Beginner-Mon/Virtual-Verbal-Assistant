## 1. `reasoning_output` / `final_answer` deduplication

**Problem**: After Phase 6.9 deleted the conversation node, `synthesizer` and
`error_handler` write the SAME value to both `reasoning_output` and `final_answer`.
The raw-vs-styled distinction the two fields encoded no longer exists — synthesizer
generates the final styled text directly. Pure tech debt from the 6.9 refactor.

**Fix** (single source of truth = `final_answer`):
- `state.py`: removed `reasoning_output` field
- `synthesizer.py`: returns only `final_answer` (both normal + fallback paths)
- `error_handler.py`: returns only `final_answer`
- `grader.py`: `_check_rules` reads `final_answer`; removed `or reasoning_output` fallback
- `tests/test_phase2_5_error.py`: `test_error_handler_writes_final_answer` + assertions
- `tests/test_phase2_5_grader.py`: `_mk_state` + all cases use `final_answer`

Verified: 101/101 unit tests pass (3 pre-existing tts_result Redis-mock failures
unrelated).

## 2. Task 1 corrections — messages table uses real columns, not JSONB

**Rationale**: `intent`, `tokens`, `grader_result` are fixed fields always present
on assistant rows. JSONB is for heterogeneous schemas (document metadata); fixed
fields belong in typed columns. NULL on user rows is fine and near-zero cost.

- `db/migrations/001_normalize_messages.sql`: dropped `metadata JSONB`, added
  `intent TEXT`, `tokens INT`, `grader_result TEXT`.
- `db/migrations/migrate_messages.py`: backfill inserts NULL for the 3 new columns
  (legacy JSONB had no such data); INSERT column list updated.
- `db/session_store.py`:
  - `write_session_turn`: new `grader_result="pass"` param; INSERT uses real columns
    (user row → NULL, assistant row → intent/tokens/grader_result)
  - `load_session_messages`: SELECT real columns; message dict exposes
    `intent`/`tokens`/`grader_result` instead of `metadata`
  - removed `_coerce_metadata` helper (no longer needed)
- `api/main.py`:
  - `_stream_chat` captures `grader_result` eagerly from node updates (like `intent`)
  - `write_session_turn(...)` call passes `grader_result`

## 3. Resume endpoint POST → GET + lazy STM

**Rationale**: `POST /sessions/{id}/resume` had a side effect (populate Redis STM),
violating GET semantics. STM warm-up is a prerequisite of `/chat`, not a feature of
resume — moved it there.

- `api/main.py`:
  - `POST /sessions/{id}/resume` → `GET /sessions/{id}` (pure read, `stm_populated=False`)
  - `/chat`: lazy STM warm-up — if `stm:{session_id}` is empty, backfill from
    PostgreSQL (last 6 messages = 3 Q&A pairs) before invoking the graph
- `ECA_UI/api.js` `resumeSession()`: `POST .../resume` → `GET /sessions/{id}` (the
  main UI's resume; `test-ui/app.js` already used GET).

## 4. Minor fixes

- **Issue 1** — `api/main.py` `delete_session`: moved inline
  `from ...session_store import _to_uuid` up to the top-level import block.
- **Issue 2** — `api/health.py` `run_all_checks`: circuit-breaker state no longer

## 5. General-query support (off-domain questions)

**Problem**: User asked "price of gold in Vietnam?" → bot refused ("I'm here to support
your physical therapy needs…"). The whole pipeline assumed every query is PT-domain:
planner had no off-topic intent, web search was OFF by default, and synthesizer chat mode
had no off-domain guidance → LLM defaulted to refusing. For a product that must also work
as a normal chatbot, this is a critical UX failure.

**Decision (Owner)**: (1) general assistant + PT specialty — never refuse off-topic;
(2) planner auto-enables web search when a turn needs external/real-time info.

**Changes**:
- `nodes/planner.py`:
  - New intent `general_query` (anything outside PT — prices, news, weather, facts)
  - New `PlanOutput.needs_web_search` field; system prompt instructs planner to set it
    for real-time/external info. Added examples (gold price → web=true; capital of France
    → web=false). Added to `_VALID_INTENTS` + return dict.
- `state.py`: new `needs_web_search: bool`
- `routing.py` `route_after_planner`: `general_query` + `needs_web_search` → retriever_agent;
  general_query without web (model already knows) → synthesizer direct.
- `nodes/retriever_agent.py`: web search enabled if USER toggle OR planner `needs_web_search`.
  System prompt: general_query uses `search_medical` (web), not pgvector (internal KB has no
  non-PT content).
- `nodes/synthesizer.py`: new `_GENERAL_TASK` mode (general-purpose assistant framing, uses
  web evidence if present, never refuses). Checked BEFORE the clinical branch so an off-PT
  query with web ToolMessages doesn't get the "expert physical therapist" prompt.
- `nodes/_persona_loader.py`: intent hint for `general_query`.

`general_query` is intentionally NOT in `graph.py` `_GRADER_REQUIRED_INTENTS` — the grader's
no-evidence / exercise-guidance rules are PT-specific; general answers go synthesizer → END.

Tests: 101/101 unit pass (3 pre-existing tts_result Redis-mock failures unrelated).
