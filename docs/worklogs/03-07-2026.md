# Kimodo CI/CD — Fix Disk Overflow & Tách Base Image
**Ngày:** 03/07/2026

---

## 1. Problem

Build `Dockerfile.prod` trên GitHub Actions fail với lỗi:

```
OSError: [Errno 28] No space left on device
```

xảy ra khi `pip install` đang tải torch (532 MB) trong builder stage. Container BuildKit hết dung lượng ngay giữa lúc tải, trước khi kịp cài xong.

**Root cause:** Mỗi lần push lên `kimodo-release`, CI build lại toàn bộ image từ đầu bao gồm: tải torch từ PyPI (532 MB), compile MotionCorrection C++, và copy source code. Torch là nguyên nhân chính gây tràn đĩa. GPU model tải hàng trăm MB vào `/tmp` của build layer, cộng với CUDA base image (~3-4 GB), vượt quá dung lượng khả dụng của runner (~14 GB sau cleanup).

Free disk space step trên runner có giúp (vì BuildKit driver `docker-container` chạy trên cùng Docker daemon, dùng chung overlay2 storage), nhưng không đủ — vấn đề gốc là *tải torch mỗi lần build*.

---

## 2. Fix

Tách **base image** (build 1 lần, hiếm khi đổi) khỏi **prod image** (build mỗi commit, chỉ COPY source code).

### 2.1 File tạo mới

| File | Mô tả |
|---|---|
| `Dockerfile.base` | Multi-stage build đầy đủ: CUDA devel → venv → torch + MotionCorrection + entrypoint. Không có CMD. |
| `.github/workflows/build-kimodo-base.yml` | Trigger khi `docker_requirements_prod.in`, `setup.py`, `pyproject.toml`, `MotionCorrection/**`, `Dockerfile.base` thay đổi + `workflow_dispatch`. Giữ Free disk space. Push ra `kimodo-base:v1`. |

### 2.2 File sửa đổi

| File | Thay đổi |
|---|---|
| `Dockerfile.prod` | Rút gọn từ 75 dòng → 15 dòng. `FROM kimodo-base:${BASE_TAG}` → COPY source → `pip install -e /workspace --no-deps` → CMD. Không còn bước tải torch / compile. |
| `.github/workflows/deploy-production.yml` | Bỏ Free disk space, bỏ cache-from/cache-to. Thêm `build-args: BASE_TAG=v1`. |

### 2.3 Luồng vận hành

```
Push code (mcp_server.py, kimodo/*) → deploy-production.yml → build Dockerfile.prod (~30s)
Push deps (requirements, MotionCorrection) → build-kimodo-base.yml → build Dockerfile.base (~15 phút)
```

### 2.4 Tag strategy

Immutable tags (`:v1`, `:v2`). Khi cần bump base: sửa `BASE_TAG` trong `deploy-production.yml` + `build-kimodo-base.yml`. `ARG BASE_TAG` trong `Dockerfile.prod` cho phép sửa 1 chỗ trong workflow thay vì sửa Dockerfile.

### 2.5 Chi tiết kỹ thuật đáng chú ý

- **`--no-cache-dir`** trong `pip install` của `Dockerfile.base`: pip không ghi cache, giảm dung lượng layer.
- **`pip install -e /workspace --no-deps`** trong `Dockerfile.prod`: refresh metadata entry-points của package `kimodo` khi `pyproject.toml` đổi, nhưng không resolve lại toàn bộ dependency tree (tránh network call).
- **`-e .` trong `docker_requirements_prod.in`**: bắt buộc giữ `COPY kimodo` trong base để editable install resolve được.

## 3. Before / After

| | Before | After |
|---|---|---|
| **Prod build time** | ~15 phút (tải torch + compile + copy) | ~30 giây (COPY source + re-link) |
| **Disk pressure** | Crash mỗi lần build (torch 532 MB) | Gần như không đáng kể |
| **Free disk space step** | Cần nhưng không đủ | Chỉ còn trong workflow build base |
| **Base rebuild frequency** | Mỗi commit | Chỉ khi deps / MotionCorrection / Dockerfile.base đổi |
| **Image coupling** | Code + deps + model trong 1 image | Tách biệt: base (deps) / prod (code) |

## 4. Lesson Learnt

> [!TIP]
> **1. Phân biệt "runner disk" và "build layer disk"**
> Trên GitHub-hosted runner với driver `docker-container`, BuildKit và Docker daemon dùng chung overlay2 storage — tức là cùng ổ đĩa vật lý. Cleanup runner disk có giúp, nhưng không giải quyết được việc build layer bị nhồi quá nhiều dữ liệu trong 1 lần chạy. Cần giảm khối lượng dữ liệu tải trong build, không chỉ tăng dung lượng.

> [!TIP]
> **2. Tách base image là pattern phổ biến cho CI/CD nặng**
> Khi build container có dependency lớn (torch, CUDA toolkit, C++ compile), tách thành base image build 1 lần giúp CI/CD từ 15 phút xuống 30 giây. Đánh đổi: cần quản lý tag version cẩn thận, thêm 1 workflow phụ. Nhưng với production, đây là đánh đổi đáng giá.

> [!TIP]
> **3. `--no-deps` quan trọng hơn tưởng tượng**
> Khi extend từ base image có sẵn venv, việc chạy `pip install -e .` mà không có `--no-deps` khiến pip gọi PyPI check toàn bộ dependency tree — phá hỏng mục đích tách base (là để tránh network call mỗi lần build). Luôn thêm `--no-deps` khi re-link editable install trên image đã có sẵn tất cả dependencies.

> [!TIP]
> **4. `-e .` trong requirements.in buộc phải giữ source code trong base image**
> Nếu `docker_requirements_prod.in` có dòng `-e .` (editable install của chính package), thì `uv pip compile` / `pip install` cần source code `kimodo/` để resolve. Không thể tách hoàn toàn source code khỏi base — phải chấp nhận bake 1 bản copy của source vào base, rồi overwrite bằng source mới trong prod.
