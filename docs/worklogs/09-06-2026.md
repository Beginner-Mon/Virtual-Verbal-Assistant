# 09/06/2026 - Amplify Auth: Domain, Managed Login, Google avatar

## Summary

Fixed Cognito domain prefix (eca-us-east-1), enabled Managed Login, mapped Google `email_verified` + `picture` claims, and wired avatar images into the UI.

---

## 1. Cognito Domain Prefix Fix

**Problem**: `backend.ts` used `userPool.addDomain('CognitoDomain', ...)` with child ID `'CognitoDomain'`, but Amplify looks for child `'UserPoolDomain'` to write `amplify_outputs.json`. Net result: domain created in AWS but output still showed random hash.

**Fix** (`amplify/backend.ts`):
- Replaced `addDomain('CognitoDomain', ...)` with direct L1 override:
  ```ts
  const cfnDomain = backend.auth.resources.userPool.node
    .tryFindChild('UserPoolDomain')
    ?.node.defaultChild as CfnUserPoolDomain;
  cfnDomain.domain = 'eca-us-east-1';
  ```

## 2. Managed Login

**Fix** (`amplify/backend.ts`):
- Added `cfnDomain.addPropertyOverride('ManagedLoginVersion', 2)` to enable Cognito's new Managed Login experience (replaces Classic Hosted UI).

## 3. Google email_verified Mapping

**Fix** (`amplify/auth/resource.ts:13`):
- Added `emailVerified: 'email_verified'` to Google OIDC attribute mapping so Cognito propagates Google's email verification status.

## 4. Google Profile Picture as Avatar

### Backend (`amplify/auth/resource.ts`)
- `profilePicture: 'picture'` already existed in attribute mapping (unchanged).

### Frontend - AuthContext (`src/contexts/AuthContext.tsx`)
- Added `picture?: string` to `FetchUserAttributesOutput` (Cognito returns standard attribute name `picture`, not `profilePicture`).

### Frontend - Avatar components
- **FloatingNavBar**: Replaced empty colored circle button with `<Avatar> + <AvatarImage>` using `userAttributes?.picture`.
- **ProfileContent**: Replaced initials `<div>` with `<Avatar> + <AvatarImage>`.
- **MobileNavBar**: Same replacement at 24px size.
- Added `referrerPolicy="no-referrer"` to all `<AvatarImage>` to bypass Google CDN (`lh3.googleusercontent.com`) Referer-based blocking.
- Removed initials text fallback — fallback is now just a colored background.

### Sizes
| Component | Before | After |
|-----------|--------|-------|
| FloatingNavBar | 32px | 36px |
| ProfileContent | 48px | 56px |
| MobileNavBar | 20px | 24px |

## 5. Amplify Auth — Enable Cognito Authentication (Session)

### `amplify_outputs.json`
- Added OAuth section with Cognito domain, Google social provider, `aws.cognito.signin.user.admin` scope, and redirect URIs (`http://localhost:5173/`).

### `src/config/amplify.ts`
- Uncommented `Amplify.configure(outputs.default)` to initialize Cognito from `amplify_outputs.json`.

### `src/components/AuthGuard.tsx`
- Passed `socialProviders={['google']}` to `<Authenticator>` so Google sign-in button appears on the login form.
- Added `AuthInner` component to fetch Cognito user attributes via `fetchUserAttributes()` on sign-in.
- Custom `handleSignOut` that clears local tokens + redirects to Cognito `/logout` to clear the Hosted UI session cookie (prevents auto-sign-in loop).

### `src/contexts/AuthContext.tsx`
- Added `FetchUserAttributesOutput` interface, `AuthUser` type, and `userAttributes` to `UserContextType`.

### `amplify/backend.ts`
- Commented out `addDomain('CognitoDomain', ...)` to fix CloudFormation sandbox error (domain `eca-us-east-1` already exists in Cognito console).
