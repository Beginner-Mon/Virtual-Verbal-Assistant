### Architecture Decisions Implemented

- **LLM Gateway**: Provider-agnostic. Gemini via `asyncio.to_thread()` wrapping sync `GeminiClientWrapper`. Anthropic/Ollama raise `NotImplementedError` (Phase 2+).
- **Manager prompt**: Simplified from `api_orchestrator.py` — returns only `intent`, `confidence`, `expanded_query`. No `action`/`needs_rag`/`generate_motion` (routing logic lives in `routing.py`).
- **Memory node**: `asyncio.gather()` for parallel STM + LTM + profile reads. Graceful degradation on every path (Redis down → empty, PG down → empty, logged as RECOVERABLE).
- **Session store**: Coexists with `memory/session_store.py` (Firebase). New LangGraph code uses PostgreSQL path.
- **Schema**: Chose plain SQL + runner script over Alembic (simpler for Phase 1, Alembic deferred to Phase 6).

### K Review: 3 Bugs Found and Fixed

#### Bug 1: `memory.py` — errors collected but never returned

`errors` list was populated by `_read_stm`, `_search_ltm`, `_get_user_profile` but not included in the return dict. RECOVERABLE errors were silently lost and never propagated to `AgentState`.

**Fix**: Added `"errors": errors` to return dict (conditional — only when non-empty).

#### Bug 2: `memory.py` — heavy objects re-created every call

`EmbeddingService()` (loads ~90MB SentenceTransformer model) and `PostgresClient()` (creates new connection pool) were instantiated fresh on every query.

**Fix**: Module-level singletons via `_get_embedding_service()` and `_get_pg_client()` lazy initializers.

#### Bug 3: `vector_backend.py` — pgvector codec registered on one connection only

`register_vector(conn)` was called on a single acquired connection, but `search()` and `insert()` acquire different connections from the pool. Those connections wouldn't have the vector type registered → runtime failure.

**Fix**: Moved pgvector registration to `postgres.py` via `asyncpg.create_pool(init=callback)`. `connect(vector=True)` registers the codec on every connection in the pool. `VectorBackend._ensure_pool()` calls `pg.connect(vector=True)`.

### K Review Verdict: APPROVED (after fixes)

Notes (non-blocking):
- `session_store.py` uses `str` for `user_id`/`session_id` but schema has `UUID` columns — may need type casting in Phase 2
