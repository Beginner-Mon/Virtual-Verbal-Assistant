## Decisions Made

### 1. DynamoDB Schema — appUserId as UUID PK

- PK = `appUserId` (UUID v4, `crypto.randomUUID()`), không dùng cognitoSub
- Fields: `appUserId`, `emailSub`, `googleSub`, `email`, `displayName`, `createdAt`
- GSIs: `emailSub-index`, `googleSub-index`, `email-index`
- 1 email → 1 row duy nhất (TransactWriteItems + EmailLocks table đảm bảo)

### 2. Race-proof email uniqueness

Dùng `EmailLocks` table + `TransactWriteItems`:

```
TransactWriteItems([
  Put: EmailLocks (ConditionExpression: attribute_not_exists(email))
  Put: UserMappings (ConditionExpression: attribute_not_exists(appUserId))
])
```

Chống concurrent signup cùng email. TTL 24h cho lock (phòng orphan).

### 3. Detect federated user

Dùng `event.request.userAttributes.identities` (JSON string), không dùng `userName.includes('_')`.

### 4. JWT claims thay vì fetch API

Inject thẳng vào JWT qua PreTokenGeneration — 5 claims:

- `custom:appUserId`
- `custom:emailSub`
- `custom:googleSub`
- `custom:displayName`
- `custom:email`

Zero network call khi mở Profile modal. Amplify `fetchAuthSession()` đọc từ local cache.

### 5. Mỗi Lambda query GSI duy nhất 1 lần

- `pre-token-generation`: GSI query để lấy `appUserId` lần đầu → inject JWT
- Business APIs (auth-status): đọc `custom:appUserId` từ verified JWT, `GetItem` trực tiếp
- Không redundant query

### 6. Chỉ PreTokenGeneration cần query GSI

PreTokenGeneration query `emailSub-index` → `googleSub-index` để resolve `custom:appUserId` lần đầu.
Mọi API khác (auth-status, set-password) dùng `custom:appUserId` từ JWT claims đã verified.

### 7. PostConfirmation creation vs PreTokenGeneration creation (pending)

| | PostConfirmation | PreTokenGeneration |
|---|---|---|
| Thời điểm | Sau confirm OTP | Lúc login lần đầu |
| UNCONFIRMED | Không có record | Không có record |
| CONFIRMED chưa login | Có record | Không có record |
| Spam email | Record vô dụng tồn tại | Chưa có record |

**Đã thảo luận, chưa implement.** PreTokenGeneration creation được ưu tiên — tránh spam.

### 8. Amplify không support attribute `name`

`defineAuth({ userAttributes })` type `UserAttributes` không có `name`. Buộc giữ `preferredUsername` với label "Display Name" trong frontend.

## Lessons Learned

### `TransactWriteItems` IAM

CDK `grantReadWriteData` **không** bao gồm `dynamodb:TransactWriteItems`. Cần thêm thủ công.

### `IFunction` vs `Function` cast

`backend.authStatusHandler.resources.lambda` typed as `IFunction` — không có `.addEnvironment()`. Cần cast `as Function`.

### 3 Lambda trigger permissions

Cognito trigger Lambdas cần 2 permissions:
1. `addPermission` (Resource policy — Cognito được invoke Lambda)
2. `addToRolePolicy` (Execution role — Lambda gọi được service khác)

### Amplify `userAttributes` type limit

`defineAuth({ userAttributes })` không support `name`. Fallback: `preferredUsername` + rename label.

### JWT claims injection

PreTokenGeneration inject claim `custom:appUserId` (cần `custom:` prefix) để tránh conflict với Cognito reserved claims. Business APIs đọc từ verified JWT claims.

### Chi phí

DynamoDB `GetItem` ≈ $0.0000005/request. Inject claim vào JWT = $0 (no network). Tối ưu hơn fetch API Gateway mỗi lần mở modal.
