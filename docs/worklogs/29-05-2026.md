# 29/05/2026 - Infra: RDS IAM Auth + SSM Parameter Store

## Summary

Migrated Lambda-to-RDS Proxy authentication from **Secrets Manager (static password)** to **IAM Authentication (short-lived tokens)** + **SSM Parameter Store (connection config)**. Encountered 2 deploy blockers: CDK DependencyCycle between DatabaseStack/LambdaStack and non-ASCII em-dash characters in Security Group descriptions rejected by AWS. Both fixed and deployed successfully.

---

## 1. RDS IAM Authentication

**Why**: Eliminate static passwords - IAM auth tokens auto-expire after 15 minutes. Reduces Secrets Manager cost ($0.40/secret/month + $0.05/10K API calls). IAM policies control connect permissions instead of shared passwords.

### Changes

#### DatabaseStack (`infra/infra/database_stack.py`)
- Enabled `iam_authentication=True` on RDS instance (RDS Proxy already had `iam_auth=True`)
- Created 4 SSM Parameters under prefix `/vva/db/`:
  - `/vva/db/proxy_endpoint` - RDS Proxy hostname
  - `/vva/db/port` - 5432
  - `/vva/db/name` - vva
  - `/vva/db/username` - vva_admin
- Exported `db_param_prefix` for LambdaStack consumption
- Kept Secrets Manager credentials (still needed for initial setup, rotation, and admin access)

#### VpcStack (`infra/infra/vpc_stack.py`)
- Removed `SecretsManagerEndpoint` (Lambda no longer reads secrets at runtime)
- Added `SsmEndpoint` (Lambda reads DB config from SSM)
- Added `StsEndpoint` (**required** - `generate_db_auth_token()` calls STS internally to sign tokens)
- Kept `CloudWatchLogsEndpoint`

#### LambdaStack (`infra/infra/lambda_stack.py`)
- Replaced `db_secret: ISecret` with `db_instance: DatabaseInstance` + `db_param_prefix: str` in constructor
- Replaced `db_secret.grant_read()` with `rds_proxy.grant_connect(fn, "vva_admin")` for all 3 Lambda functions
- Added IAM policy `ssm:GetParametersByPath` + `ssm:GetParameter` on `/vva/db/*`
- Env vars: `DB_PARAM_PREFIX=/vva/db` replaces `RDS_PROXY_ENDPOINT` + `DB_SECRET_ARN` + `DB_NAME`
- Import: `aws_iam as iam` replaces `aws_secretsmanager as secretsmanager`

#### app.py
- Passes `db_instance=db_stack.db_instance` + `db_param_prefix=db_stack.db_param_prefix` instead of `db_secret=db_stack.db_secret`

#### shared/db.py (`lambda/layer/shared/db.py`)
- Removed `_get_secret()` (Secrets Manager call)
- Added `_get_config()` - reads SSM Parameter Store, cached permanently across warm invocations
- Added `_get_auth_token()` - calls `rds.generate_db_auth_token()`, cached for 14 minutes (token expires at 15)
- `get_connection()` uses IAM token as password instead of static password
- All query helpers unchanged (`to_uuid`, `fetch_all`, `fetch_one`, `_serialize_value`)
- 3 handler files (list_sessions, delete_session, resume_session) **unchanged** - they only call `get_connection()`, interface preserved

## 2. Bug fix: CDK DependencyCycle

**Symptom**: `cdk synth` reported DependencyCycle between `VvaDbStack` and `VvaLambdaStack`.

**Root cause**: In LambdaStack, `sg_rds_proxy.add_ingress_rule(peer=self.sg_lambda)` **modifies a resource owned by DatabaseStack** (adds ingress rule referencing LambdaStack's `sg_lambda` into DatabaseStack's CloudFormation template). CDK creates bidirectional dependencies:
- LambdaStack depends on DatabaseStack (needs `sg_rds_proxy`, `rds_proxy`, ...)
- DatabaseStack depends on LambdaStack (ingress rule references `sg_lambda`)
- -> Circular dependency

**Fix**: Replaced `sg_rds_proxy.add_ingress_rule()` with `ec2.CfnSecurityGroupIngress()`:
```python
ec2.CfnSecurityGroupIngress(
    self, "SgRdsProxyIngressFromLambda",
    group_id=sg_rds_proxy.security_group_id,
    ip_protocol="tcp",
    from_port=5432,
    to_port=5432,
    source_security_group_id=self.sg_lambda.security_group_id,
    description="PostgreSQL from Lambda",
)
```
`CfnSecurityGroupIngress` creates the resource **within LambdaStack's template**, only reading SG IDs from DatabaseStack (one-way). DatabaseStack is not modified -> cycle broken.

## 3. Bug fix: Non-ASCII em-dash in Security Group description

**Symptom**: `cdk deploy` failed with `Character sets beyond ASCII are not supported` on both `SgRds` and `SgRdsProxy`.

**Root cause**: Descriptions contained Unicode em-dash characters (U+2014) instead of ASCII hyphens (U+002D). AWS EC2 API rejects non-ASCII in Security Group descriptions.

**Fix**: Replaced all em-dash characters with ASCII hyphens across all `.py` files in the infra directory.

## 7. Lessons learned

1. **`add_ingress_rule()` cross-stack = DependencyCycle** - Modifying Stack A's SG from Stack B creates bidirectional dependency. Use `CfnSecurityGroupIngress` to keep the resource in the current stack.
2. **AWS EC2 rejects non-ASCII in Security Group descriptions** - ASCII only. Em-dashes, smart quotes, and other Unicode characters are all rejected.
3. **STS VPC Endpoint is mandatory for IAM Auth** - `generate_db_auth_token()` calls STS internally. Without STS endpoint, Lambda in isolated subnets will timeout.
4. **IAM Auth token cache at 14 minutes** - Token expires at minute 15. Refresh early to avoid race conditions near expiry boundary.
