## 3. K Review: 5 Bugs Found and Fixed

### Bug 1 (CRITICAL): `vector_backend.py` — `search()` SQL missing `source_type`

SQL `SELECT id, content, metadata, ...` didn't include `source_type` column. Both `_assess_quality()` (retrieval.py) and `_format_retrieval_context()` (reasoning.py) read `metadata.source_type` — always fell through to defaults.

**Fix**: Added `source_type` to SELECT. Merged into metadata dict: `{**(row["metadata"] or {}), "source_type": row["source_type"]}`.

### Bug 2 (SIGNIFICANT): `reasoning.py` — exercise prompt duplicated memory content

`formatted_profile` and `formatted_memory` both received `_format_memory_context()` output. The exercise prompt's "Patient Profile" and "Memory Context" sections were identical — wasted tokens + confused LLM.

**Fix**: Created `_format_user_profile()` helper that extracts only `user_profile` dict. Exercise prompt now shows distinct content in each section.

### Bug 3 (SIGNIFICANT): `reasoning.py` — exercise prompt missing conversation history

`_EXERCISE_PROMPT` had no `{formatted_history}` placeholder. Follow-up exercise queries lost all conversational context.

**Fix**: Added `## Conversation History` section to exercise prompt + `formatted_history` parameter in `.format()` call.

### Bug 4 (MINOR): `retrieval.py` — web search similarity used weight value

Web search results had `similarity=_SOURCE_WEIGHTS.get("web_search", 0.75)` — conflated similarity with weight. In `_assess_quality`, this caused double-weighting: `0.75 * 0.75 = 0.5625`.

**Fix**: Changed to fixed `similarity=0.7` per spec.

### Bug 5 (MINOR): `test_phase2_integration.py` — flaky intent assertion

`test_full_graph_exercise_recommendation` asserted `intent == "exercise_recommendation"` but Manager could classify the Vietnamese query as `knowledge_query`. Both are valid.

**Fix**: Allow both `exercise_recommendation` and `knowledge_query` in assertion.

## 4. Architecture Decisions

- **Shared singletons** (`shared.py`): EmbeddingService (~90MB model) and PostgresClient (connection pool) shared across memory + retrieval nodes via module-level lazy init.
- **Multi-source parallel search**: retrieval uses `asyncio.gather(*search_tasks, return_exceptions=True)` to search multiple source_types simultaneously.
- **Quality-gated web fallback**: web search only triggers when pgvector results are below `min_context_threshold` (count) or `quality_threshold` (weighted avg similarity).
- **Two prompt templates**: `_KNOWLEDGE_PROMPT` (general health) vs `_EXERCISE_PROMPT` (PT-specific with patient profile + constraints). Selected by intent.
- **CRITICAL error on LLM failure**: reasoning node returns CRITICAL → error routing → error_handler → graceful apology. Pipeline doesn't hang.
- **No HyDE / reflection / query reformulation**: Manager already provides expanded_query. Heavyweight loops deferred to Phase 6.
