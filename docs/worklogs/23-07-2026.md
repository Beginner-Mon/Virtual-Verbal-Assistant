## Việc 3 — Live-verify việc 2 lộ ra 2 ROOT CAUSE khiến SSE không hề stream thật

### Bug A — server-side: LangGraph custom-stream drain starvation (synthesizer.py)
- **Triệu chứng đo được** (log timestamp tại đúng chỗ `yield` token trong main.py):
  371 token dồn hết vào ~2.6s cuối, kết thúc đúng lúc `node_complete` — trong khi model
  sinh suốt ~6.5s. Node càng dài, im lặng càng lâu.
- **Cơ chế** (đọc source langgraph 1.2.1 `pregel/main.py` + `_runner.py`): `writer()` đẩy
  vào AsyncQueue ngay, nhưng queue chỉ được drain khi "waiter task" (`stream.wait()`)
  thắng trong `asyncio.wait(..., FIRST_COMPLETED)`. Vòng `async for chunk in llm.astream`
  tự resume liên tục nhanh hơn asyncio kịp lập lịch cho waiter → waiter chỉ chạy khi node
  xong → burst.
- **Fix**: `await asyncio.sleep(0)` sau mỗi `writer()` — ép nhường event loop 1 tick/token.
- **Verify đo lại**: token trải đều 15.88s (avg gap ~19ms, khớp tốc độ model); gap lớn duy
  nhất 8.8s = đúng khoảng chờ grader-retry giữa 2 pass, không phải lỗi.

### Bug B — client-side: CRLF boundary mismatch (api.ts)
- Sau khi fix A, browser VẪN nhận 1041 event trong 27ms → còn 1 lớp buffer khác.
- **Loại trừ bằng test cô lập** (Playwright, fetch thô từ origin :5173, không qua code
  app): stream tốt cả có lẫn không có `resp.clone()` → lỗi nằm trong `streamChat`.
- **Bằng chứng byte-level** (`od -c` response thật): sse-starlette kết block bằng
  `\r\n\r\n`, nhưng vòng đọc tìm boundary bằng `buffer.lastIndexOf('\n\n')` — literal
  `\n\n` không bao giờ khớp → mọi chunk `continue` → toàn bộ parse dồn vào flush cuối sau
  `done`. (`_parseSSEBlocks` thì split đúng `/\r?\n\r?\n/` nên flush cuối vẫn ra đủ event
  — một cục.)
- **Fix**: tìm boundary bằng regex `/\r?\n\r?\n/g` (lấy match cuối, cắt đúng độ dài match).
- tsc 0 lỗi.
