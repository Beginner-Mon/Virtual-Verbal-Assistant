## 1. Intent 6-enum → 3 trục (Planner)

Bỏ `intent` enum. PlanOutput mới:
```python
required_outputs: list[str]   # tag ∈ TAG_RULES (grader đọc)
resolved_query:   str         # coreference đã resolve, GIỮ SẠCH
needs_retrieval:  bool        # cổng retriever
needs_motion:     bool        # hard-gate Kimodo
```
Bỏ: intent, expanded_query→resolved_query, scope, search_strategy, constraints_detected,
is_clinical, notes, confidence, 3 flag needs_kb/web/memory.

**Lý do**: 1 enum gánh 3 việc (routing/contract/framing) → tách 3 trục độc lập. Flags > enum
(bật nhiều tool cùng lúc). Manager (planner) ra WHAT, dev (retriever) tự lo HOW.

## 2. Hai cổng độc lập (sửa lỗi an toàn)

`Cổng retriever ⟸ needs_retrieval` ; `Cổng grader ⟸ required_outputs != []`. KHÔNG gộp.
Gộp = bug an toàn: "đau ngực khi tập" (needs_retrieval=false NHƯNG có red_flag_screen) sẽ skip
grader → cảnh báo không được ép. (D2, D15)

## 3. Retriever (5 tình huống biên — D23-D28)

- Input: chỉ `resolved_query` + `required_outputs` + `grader_feedback`. KHÔNG memory_context
  (retrieval ≠ personalize — D20).
- Tự chọn kb/web/memory, gọi SONG SONG. Motion KHÔNG ở đây.
- Empty `{found:[]}` ≠ error `{error}`: empty→synthesizer (không retry vì query không đổi),
  error→retry→error_handler.
- Out-of-scope = tag `referral_advice` (KHÔNG severity enum). Clinical-no-source → refuse không bịa.
- Web-off + cần real-time = instance của no-source.
- Tool-result: cap top-k 5/3/3 (~3.8k tok, không tràn 64k).

## 4. Motion = node riêng (D26 revised)

coherence qua tag `motion_descriptor` (synthesizer viết mô tả) + UI ghép text+video.

## 5. Synthesizer (M.3b)

## 7. Memory (M.4-M.8)

- Schema: seq_id BIGSERIAL (global, có gap), summaries chunk đóng băng + `status` (GDPR),
  user_memory (gom profile), kb_embeddings (FK documents, sửa A4), documents.external_id TEXT
  (sửa bug A2 youtube). e5-small vector(384) + prefix query:/passage:.
- **Bỏ user_id khỏi messages + summaries** (D19): chỉ session_id. Tenant-scope ở tool function,
  GDPR qua cascade, RLS chưa cần (một-cửa). 3NF sạch.
- memory_search 2-step (session_ids của user → ANY); topic→vector, temporal→filter SQL.
- Summary: 1 ngưỡng 10k token, chạy nền, đóng băng 1 lần (không drift), CAS idempotent.
- Prompt caching: tĩnh đầu/động cuối; DeepSeek tự cache prefix (không cần cache_control).
- GDPR: mark-dirty app-logic (summaries không FK→messages), hard-delete, regen embedding.
