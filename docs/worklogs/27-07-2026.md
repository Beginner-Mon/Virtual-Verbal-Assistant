# Planning → Implementation — ALB Endpoint cho Kimodo MCP

**Ngày:** 27/07/2026
**Plan:** K (Mr. Senryuu) | **Implement:** K (theo chỉ đạo trực tiếp của N) | **Deploy:** N (pending)

---

## 1. Problem

Kimodo MCP server đã chạy trên ECS (EC2 `g5.xlarge`, awsvpc) nhưng không có endpoint để test: task ENI có IP riêng và đổi mỗi lần restart; gán public IP cho EC2 host vô nghĩa với awsvpc mode.

## 2. Decision

Dùng **ALB internet-facing** làm stable endpoint. N sẽ cleanup sau khi test nhưng ALB là thành phần chắc chắn dùng lại → thiết kế toggle bằng module constant `ENABLE_ALB` để teardown/re-provision bằng 1 dòng + `cdk deploy`.

**Full plan:** `.claude/plans/kimodo-alb-endpoint.md`

## 3. Implementation (27/07)

### 3.1 Thay đổi

File duy nhất: `infra/infra/kimodo_ecs_stack.py` (~120 dòng thêm + sửa).

| Mục | Chi tiết |
|---|---|
| Constants | `ENABLE_ALB = True`, `ALB_ALLOWED_CIDR` (warning IP/32), `VPC_CIDR` |
| SG ALB | `kimodo-sg-alb`, ingress TCP 80 từ `ALB_ALLOWED_CIDR` |
| SG ECS | Khi `ENABLE_ALB`: ingress 8000 từ ALB SG + VPC CIDR. Khi False: ingress 8000 từ any_ipv4 (trạng thái hiện tại) |
| ALB | `kimodo-alb`, internet-facing, EcsPublic subnets, `idle_timeout=300s` |
| TG | `kimodo-mcp-tg`, `target_type=ip`, port 8000, health `/mcp` matcher 200-499, dereg 30s |
| Listener | :80, `open=False` (giữ SG rule theo `ALB_ALLOWED_CIDR`) |
| Container HC | `curl -fsS` → `curl -sS -o /dev/null` (FastMCP trả 406 cho GET thuần) |
| Service | **L1 `CfnService`** (bypass L2 synth-validation `hasEc2Capacity`). CP strategy `kimodo-GPU` weight=1 base=0, `minHealthy=1`, `maxPercent=200`, `assignPublicIp=DISABLED` — khớp 100% config service thủ công (đối chiếu từ `describe-services`), chỉ khác: `desiredCount=1` (để chạy), `gracePeriod=600` (an toàn hơn). TG attach qua `LoadBalancers` property. |
