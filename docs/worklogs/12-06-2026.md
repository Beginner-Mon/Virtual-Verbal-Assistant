### T1.2 — Fix tenant leak SQL (A1 tái xuất)

Step 2 của `memory_search` (cả 2 nhánh có/không `since_days`):
```sql
-- Trước (LEAK):
WHERE s.session_id != $2 AND s.status = 'active'

-- Sau (FIXED):
WHERE s.session_id = ANY($ids) AND s.session_id != $current AND s.status = 'active'
```
`$ids` lấy từ Step 1 (`user_session_ids`) — trước đó fetch xong rồi vứt đi.

## PR 2 — Background summarizer M.5

### T2.1 — Trigger logic

Module mới `nodes/summarizer.py`:
- `maybe_summarize(session_id)` — gọi sau `write_session_turn` trong `api/main.py`
- Lấy `MAX(covers_up_to_seq)` từ summaries → tính token chưa nén
- `token_count` ưu tiên, fallback `len(content)//4`
- ≥ 10k (D13) → fire `asyncio.create_task` (pattern y hệt `_pending_tts_tasks`)
- Dưới ngưỡng → return (không block)

### T2.2 — Summarize chunk

`_run_summarize(session_id, from_seq)`:
1. Load messages trong khoảng `(from_seq, latest]`
2. LLM summarize (dùng `get_chat_model("planner")` tier — model rẻ)
3. `embed_passage()` — e5 prefix `passage:` (D10)
4. INSERT với `ON CONFLICT ON CONSTRAINT uq_chunk DO NOTHING` (CAS idempotent)

### T2.3 — Edge A (summarize fail)

- Retry 1 lần (wait 0.5s giữa retry)
- Vẫn fail → log ERROR, return (turn sau trigger lại)
- Hard cap: memory node đã có `_select_recent_raw` với token budget (không cần code thêm)

### Integration vào API

- `api/main.py`: thêm `_pending_summarizer_tasks` set + gọi `maybe_summarize(req.session_id)` sau khi session persisted
- Import lazy trong `summarizer.py` → không cycle

### Tests PR2

- `test_pr2_summarizer.py` — 10 tests:
  - 4 threshold tests: dưới ngưỡng không fire, trên ngưỡng fire, token từ prior summary + estimate null
  - 1 CAS test: verify `ON CONFLICT ON CONSTRAINT uq_chunk` trong SQL
  - 3 LLM tests: summarize thành công, empty response, retry 1 lần
  - 2 edge case tests: DB error, empty messages
